# Ghosium full-source engine fork

This directory defines the controlled transition from the v0.7.0 distribution layer to a full-source Ghosium engine build.

## Source lock

`ENGINE_REVISION` remains the Windows snapshot revision used by the stable lightweight release path. `ENGINE_SOURCE_REVISION` pins the corresponding upstream source commit used by the full-source path. `engine/branding/product.json` records both values and is validated by CI.

The source checkout must be detached at the exact commit in `ENGINE_SOURCE_REVISION`. Production full-source builds must never build from `HEAD`, `main`, an unpinned branch, or a floating tag.

## Scope of Ghosium-owned engine changes

Source-level Ghosium branding is applied only to product-controlled surfaces. The first implementation targets:

- product and short product names;
- About and Settings product strings;
- first-run and accessibility welcome strings;
- application icons and Windows file/version resources;
- Ghosium-owned Help, Update, Security, Search and Store routing;
- first-party extension-store integration;
- default-search integration;
- Ghosium-specific update metadata and provenance surfaces.

Normal browsing is never restricted to Ghosium domains. The URL allowlist applies only to links generated by Ghosium-owned product UI.

## Legal boundary

Upstream and third-party copyright, license and attribution material is not branding and must not be removed or rewritten as Ghosium-owned material. It remains available through the dedicated legal/third-party surface and the files required by upstream licenses.

`THIRD_PARTY_NOTICES.md`, upstream license files and generated third-party notices are release requirements.

## Security invariants

The source fork must not weaken:

- Chromium sandboxing and Windows exploit mitigations;
- renderer/site/process isolation;
- TLS certificate validation or revocation handling;
- extension permission and signature enforcement;
- Safe Browsing or equivalent security protections unless a reviewed Ghosium replacement provides equal or stronger protection;
- signed update verification;
- memory-safety or control-flow protections enabled by the upstream toolchain.

Privacy changes must be narrowly scoped to unnecessary telemetry/background product services and must not disable security-critical networking.

## Build model

The full-source engine is intentionally separate from the normal hosted v0.7.x snapshot workflow because a Chromium source checkout and compile require substantially more disk, RAM and build time.

The expected workstation/builder flow is:

1. run `scripts/bootstrap-engine-source.ps1` to prepare a pinned checkout;
2. run `scripts/apply-engine-branding.ps1` against the checkout;
3. run `scripts/verify-engine-fork.ps1` to enforce Ghosium product and legal/security invariants;
4. compile with the upstream GN/Ninja toolchain using the Ghosium build arguments documented here;
5. run browser, sandbox, certificate, extension, startup, accessibility and low-memory test suites;
6. package only after provenance and binary metadata checks pass.

## Build arguments

The fork remains an open-source Chromium-derived build and must not impersonate Google Chrome branding. Use Chromium branding as the upstream base and apply Ghosium-owned resources on top. Do not set Google Chrome branding flags or introduce proprietary Google API keys as a branding mechanism.

A full-source Windows build should retain upstream security defaults and add Ghosium-specific release hardening through reviewed GN arguments rather than disabling components to make a build pass.

## Store architecture

`store.ghosium.com` is a first-party consumer extension store, not an enterprise-policy deployment mechanism. Engine integration must use a reviewed public-store install/update path with:

- signed extension packages;
- package SHA-256 verification;
- signature/key verification;
- explicit permission review before installation;
- malware scanning and quarantine state;
- signed update manifests;
- emergency revocation data;
- rollback-safe update handling.

## Search architecture

`search.ghosium.com` remains the Ghosium default search endpoint. Its PHP + JSON implementation stays independent from the engine source and must not require SQL. Search results remain ordinary web URLs and are not subject to the Ghosium product-link allowlist.

## Languages

The full-source product contract contains exactly 30 supported locales. English (`en-US`) is the default and Croatian (`hr`) is mandatory. Engine string work must keep these locales buildable and must fall back to English when a Ghosium-specific translation is not yet available rather than exposing upstream product branding.
